# Fitlog 기능별 UX 요구사항

2026-10-11 · 0.1.3 · 사용자 확정 · [HAN-8](https://linear.app/hanzicho/issue/HAN-8)

## 1. 목적과 우선순위
생활관리를 최소한의 노력으로 수행한다. PC 기본 화면에서 체크·달성률·연속 기록·월 달력·사진을 확인하며 채팅 입력도 줄인다. 이 개정은 이전 DESIGN 및 UX의 3상태 버튼·상세 화면·앱 내 업로드/카메라/폴더 입력을 대체한다. 과거 변경 내역은 CHANGELOG에 보존한다. 현재 단계/전이는 [PROJECT](../PROJECT.md), 실제 검증 범위는 [VALIDATION](../VALIDATION.md)을 따른다.

## 2. UX-001 — 제목과 설정만
1. 상단은 ‘오늘의 체크리스트’와 톱니바퀴 한 개. FITLOG·날짜·새로고침·상세 보기·중복 제목을 제거한다.
2. 톱니바퀴는 내 프로필/개인 정보·영양 목표/알림 설정을 한 영역에 연다. 닫기와 Escape를 지원한다. 데이터 전송 안내는 설정에만 둔다.
3. 15초 주기와 창 활성화 시 자동 조회. 실제 오류에만 다시 연결 표시. 저장 실패/충돌을 성공으로 숨기지 않는다.
4. 수용: 기본 화면 도구 최소화, 설정 저장 후 유지, 키보드 조작. 코드: `ui/src/main.tsx`, `compact.tsx`, `ConfigPanel.tsx`.

## 3. UX-002 — 단일 체크박스 또는 횟수
1. PC 상단 왼쪽 절반, 한 행당 한 항목, 세로 스크롤. 내용 옆 조작 하나만 둔다.
2. controlType enum은 `binary`/`count`. binary: 미체크=미달성, 체크=달성. count: 현재/목표(예: 50/100), Enter 또는 포커스 이동 시 저장; 현재≥목표면 달성, 감소하면 재계산한다.
3. AI는 사용자 항목을 읽어 유형과 label을 선택한다. 명시된 횟수 목표만 저장하며 수치를 발명하지 않는다. UI에는 유형 드롭다운/실행 상태/미작성 버튼이 없다.
4. 기존 `unwritten`과 occurrence는 과거 데이터/백업·구버전 클라이언트 호환을 위해 내부 보존한다. 과거 미작성/no는 모두 미체크로 표시한다. 저장 버전 충돌을 검사하며 자동 조회 후 오류를 알린다.
5. 현재 슬롯/분모는 운동·아침·점심·저녁 N=4이다. 슬롯별 label과 유형은 채팅에서 설정한다. 임의 항목 추가/날짜별 목표 집합 버전은 후속 범위.
6. 수용: 클릭 즉시 표시, 저장·재접속·횟수 증감·충돌·백업 복원. 코드: `Checks.tsx`, `src/contracts/experience.ts`, `src/application/journal.ts`.

## 4. UX-003 — 오른쪽 지표 유지
1. 최다·현재 연속 기록과 오늘 목표 원형 뷰를 동시에 표시한다. 좌우 폭은 동일하다.
2. 원형은 달성한 목표 K/N. binary=yes 또는 count≥target만 달성이다. 사진/활동 존재만으로 달성시키지 않는다.
3. 연속 기록은 기록을 남긴 날을 센다. 미달성을 기록한 날도 포함하고 예정만 있는 날은 제외한다. 체크로 활동 건수를 만들어내지 않는다.
4. 수용: 체크/카운터 변경 후 지표 갱신, 동일 폭, 기록 집계 구분. 코드: `DailyMetrics.tsx`, `src/domain/goals.ts`, `progress.ts`, `src/application/service.ts`.

## 5. UX-004 — 채팅 첨부 전용 이미지북
1. 앱 내 업로드·카메라·촬영 폴더·분석 편집/재시도 버튼을 제거한다. 첨부와 분석 수정/삭제는 채팅의 MCP 도구로 수행한다.
2. 호스트가 채팅 첨부의 실제 bytes를 전달할 수 있어야 add_meal_photo로 저장할 수 있다. 접근 불가 시 저장했다고 주장하지 않는다. 실제 호스트 첨부→도구 라우팅은 별도 수용 항목이다.
3. 사진은 날짜/끼니/title로 로컬 저장한다. 기본 이름은 ‘오늘의 아침식사’ 등이며 과거 날짜는 날짜를 사용한다. 이름 옆에는 ‘약 600 kcal’처럼 추정치를 표시한다.
4. 사진 아래는 정적 가로 pill 피드백(최대 3개). 동작이 없으므로 가짜 클릭 버튼으로 만들지 않는다. enum과 기본 문구: balanced=균형 잡힌 식사; protein_low=단백질을 더해요; overeating=양을 조금 줄여요; high_calorie=칼로리가 높아요; vegetables_low=채소를 더해요; meal_suggestion=짧은 식사 추천(예: 저녁은 고등어를 추천해요).
5. AI는 실제 이미지와 저장 개인 정보/목표를 참고한다. 불명확한 양·누락된 섭취로 균형/과식을 단정하지 않는다. 분석 없는 사진은 분석 대기, 구버전 분석의 feedback 누락은 빈 배열이다. UI는 임의 영양 평가를 생성하지 않는다.
6. 날짜 선택·이전/다음 탐색, 신규 사진 자동 선택, 재조회 시 기존 선택 유지. 이미지 비율에 프레임을 맞추고 빈 테두리/업로드 안내를 두지 않는다.
7. 수용: 채팅 저장 시뮬레이션 후 자동 조회·탐색·pill·날짜 왕복·이미지 크기 일치. 코드: `Imagebook.tsx`, `compact.css`, `src/mcp/main.ts`, `src/application/journal.ts`.

## 6. UX-005 — 큰 월 달력과 목표 잔디
1. PC 달력 폭 300px, 날짜 칸 35px 이상으로 확대한다. 좁은 화면은 전체 폭으로 표시한다.
2. K=0은 빈 색, 0<K<N은 min(3, ceil(3*K/N)), K=N은 가장 진한 level-4. 현재 N=4의 0~4 색은 각각 대응한다. N=0은 0이다.
3. 횟수 미달·미체크·예정·사진 존재는 달성 제외. 날짜 선택은 이미지북을 바꾼다. 미래 저장은 금지한다.
4. 수용: 폭 측정, 농도 0~4, 중복/가변 N/필터 독립성/해제 감소. 코드: `src/domain/goals.ts`, `compact.tsx`, `compact.css`.

## 7. UX-006 — 짧은 채팅 취합
1. get_profile로 날짜를 확인하고 명확한 활동 사실은 create_activity, 체크/횟수는 get_day_journal/set_day_check로 저장한다. 같은 요청 재시도는 같은 idempotencyKey를 쓴다.
2. 기존 명시적 체크를 보존한다. 음식 이름/활동 존재만으로 목표 준수를 판정하지 않는다. 예정은 달성하지 않는다. 결과가 달라지는 모호함만 질문한다.
3. 사진은 실제 첨부 bytes 저장→실제 이미지 분석→save_photo_analysis→해당 날짜 재조회 순서. 저장 성공/분석 성공/실제 Codex 화면 수용을 구분한다.
4. 수용: stdio MCP/SQLite·재시작과 브라우저 자동 조회. 실제 자연어/첨부 전달·AI 품질은 호스트 수용에서 확인한다. 코드: `src/mcp/main.ts`, `ui/src/bridge.ts`, `main.tsx`.
