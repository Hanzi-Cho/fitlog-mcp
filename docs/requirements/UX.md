# Fitlog 기능별 UX 요구사항

2026-10-11 · 0.1.5 · 사용자 확정 · [HAN-8](https://linear.app/hanzicho/issue/HAN-8)

## 1. 목적과 우선순위
생활관리를 최소한의 노력으로 수행한다. PC 기본 화면에서 체크·달성률·연속 기록·월 달력·사진을 확인하며 채팅 입력도 줄인다. 이 개정은 이전 DESIGN 및 UX의 3상태 버튼·상세 화면·앱 내 업로드/카메라/폴더 입력을 대체한다. 과거 변경 내역은 CHANGELOG에 보존한다. 현재 단계/전이는 [PROJECT](../PROJECT.md), 실제 검증 범위는 [VALIDATION](../VALIDATION.md)을 따른다.

## 2. UX-001 — 제목과 설정만
1. 상단은 ‘오늘의 체크리스트’와 톱니바퀴 한 개. FITLOG·날짜·새로고침·상세 보기·중복 제목을 제거한다.
2. 톱니바퀴는 내 프로필/개인 정보·영양 목표/알림 설정을 한 영역에 연다. 닫기와 Escape를 지원한다. 데이터 전송 안내는 설정에만 둔다.
3. 15초 주기와 창 활성화 시 자동 조회. 실제 오류에만 다시 연결 표시. 저장 실패/충돌을 성공으로 숨기지 않는다.
4. 수용: 기본 화면 도구 최소화, 설정 저장 후 유지, 키보드 조작. 코드: `ui/src/main.tsx`, `compact.tsx`, `ConfigPanel.tsx`.

## 3. UX-002 — 단일 체크박스 또는 횟수
1. PC 상단 오른쪽 절반, 한 행당 한 항목, 세로 스크롤. 내용 옆 조작 하나만 둔다.
2. controlType enum은 `binary`/`count`. binary: 미체크=미달성, 체크=달성. count: 현재/목표(예: 50/100), Enter 또는 포커스 이동 시 저장; 현재≥목표면 달성, 감소하면 재계산한다.
3. AI는 사용자 항목을 읽어 유형과 label을 선택한다. 명시된 횟수 목표만 저장하며 수치를 발명하지 않는다. UI에는 유형 드롭다운/실행 상태/미작성 버튼이 없다.
4. 기존 `unwritten`과 occurrence는 과거 데이터/백업·구버전 클라이언트 호환을 위해 내부 보존한다. 과거 미작성/no는 모두 미체크로 표시한다. 저장 버전 충돌을 검사하며 자동 조회 후 오류를 알린다.
5. 기본 목록은 운동·아침·점심·저녁 N=4이며 작업 추가·제거에 따라 N이 달라진다. 날짜별 목표 집합은 UX-008의 이력으로 보존한다.
6. 수용: 클릭 즉시 표시, 저장·재접속·횟수 증감·충돌·백업 복원. 코드: `Checks.tsx`, `src/contracts/experience.ts`, `src/application/journal.ts`.

## 4. UX-003 — 왼쪽 지표 유지
1. 최다·현재 연속 기록과 오늘 목표 원형 뷰를 동시에 표시한다. 좌우 폭은 동일하다.
2. 원형은 달성한 목표 K/N. binary=yes 또는 count≥target만 달성이다. 사진/활동 존재만으로 달성시키지 않는다.
3. 연속 기록은 기록을 남긴 날을 센다. 미달성을 기록한 날도 포함하고 예정만 있는 날은 제외한다. 체크로 활동 건수를 만들어내지 않는다.
4. 수용: 체크/카운터 변경 후 지표 갱신, 동일 폭, 기록 집계 구분. 코드: `DailyMetrics.tsx`, `src/domain/goals.ts`, `progress.ts`, `src/application/service.ts`.

## 5. UX-004 — 채팅 첨부 전용 이미지북
1. 앱 내 업로드·카메라·촬영 폴더·분석 편집/재시도 버튼을 제거한다. 첨부와 분석 수정/삭제는 채팅의 MCP 도구로 수행한다.
2. 호스트가 채팅 첨부의 실제 bytes를 전달할 수 있어야 add_meal_photo로 저장할 수 있다. 접근 불가 시 저장했다고 주장하지 않는다. 실제 호스트 첨부→도구 라우팅은 별도 수용 항목이다.
3. 사진은 날짜/끼니/title로 로컬 저장한다. 기본 이름은 ‘오늘의 아침식사’ 등이며 과거 날짜는 날짜를 사용한다. 이름 옆에는 ‘약 600 kcal’처럼 추정치를 표시한다.
4. 사진 아래는 정적 가로 pill 피드백(최대 3개). 동작이 없으므로 가짜 클릭 버튼으로 만들지 않는다. enum과 기본 문구: balanced=균형 잡힌 식사; protein_low=단백질을 더해요; overeating=양을 조금 줄여요; high_calorie=칼로리가 높아요; vegetables_low=채소를 더해요; meal_suggestion=짧은 식사 추천(예: 저녁은 고등어를 추천해요).
5. AI는 실제 이미지와 저장 개인 정보/목표를 참고한다. 불명확한 양·누락된 섭취로 균형/과식을 단정하지 않는다. 분석 없는 사진은 분석 대기, 구버전 분석의 feedback 누락은 빈 배열이다. UI는 임의 영양 평가를 생성하지 않는다.
6. 날짜 선택·이전/다음 탐색, 신규 사진 자동 선택, 재조회 시 기존 선택 유지. 이미지 비율에 프레임을 맞추고 빈 테두리/업로드 안내를 두지 않는다.
7. 수용: 채팅 저장 시뮬레이션 후 자동 조회·탐색·pill·날짜 왕복·이미지 크기 일치. 코드: `Imagebook.tsx`, `compact.css`, `src/mcp/main.ts`, `src/application/journal.ts`.

## 6. UX-005 — 큰 월 달력과 목표 잔디
1. PC 달력 폭 240px, 날짜 칸 28px(낮은 창 24px)로 조절한다. 좁은 화면은 전체 폭으로 표시한다.
2. K=0은 빈 색, 0<K<N은 min(3, ceil(3*K/N)), K=N은 가장 진한 level-4. 기본 N=4의 0~4 색은 각각 대응하며 변경 후 N은 해당 날짜의 목표 집합을 따른다. N=0은 0이다.
3. 횟수 미달·미체크·예정·사진 존재는 달성 제외. 날짜 선택은 이미지북을 바꾼다. 미래 저장은 금지한다.
4. 수용: 폭 측정, 농도 0~4, 중복/가변 N/필터 독립성/해제 감소. 코드: `src/domain/goals.ts`, `compact.tsx`, `compact.css`.

## 7. UX-006 — 짧은 채팅 취합
1. get_profile로 날짜를 확인하고 명확한 활동 사실은 create_activity, 체크/횟수는 get_day_journal/set_day_check로 저장한다. 같은 요청 재시도는 같은 idempotencyKey를 쓴다.
2. 기존 명시적 체크를 보존한다. 음식 이름/활동 존재만으로 목표 준수를 판정하지 않는다. 예정은 달성하지 않는다. 결과가 달라지는 모호함만 질문한다.
3. 사진은 실제 첨부 bytes 저장→실제 이미지 분석→save_photo_analysis→해당 날짜 재조회 순서. 저장 성공/분석 성공/실제 Codex 화면 수용을 구분한다.
4. 수용: stdio MCP/SQLite·재시작과 브라우저 자동 조회. 실제 자연어/첨부 전달·AI 품질은 호스트 수용에서 확인한다. 코드: `src/mcp/main.ts`, `ui/src/bridge.ts`, `main.tsx`.


## 8. UX-007 — 달력과 날짜 기록 탐색
1. 기본 선택은 오늘. 과거 날짜 클릭 시 이미지북 첫 슬라이드에 그날 작업 목록/달성·미달성 또는 현재/목표 횟수를 읽기 전용으로 표시한다. 이후 슬라이드는 해당 날짜 사진과 영양 피드백이다.
2. 선택 중인 과거 날짜 재클릭 시 선택 해제→오늘 및 현재 월로 복귀한다. 오늘 사진이 없으면 ‘아직 사진이 없어요’를 이미지 영역 가로·세로 중앙에 표시한다. 장식 테두리는 두지 않는다.
3. 상단 목록·연속 기록·원형 지표는 snapshot.today를 따르며 달력 탐색에 영향받지 않는다. 날짜 변경 시 첫 슬라이드로 초기화하며 지연 응답으로 다른 날짜가 섞이지 않도록 한다.
4. 코드: ui/src/compact.tsx, Imagebook.tsx, compact.css. 수용: 기본 오늘/과거 목록→사진/왕복/과거 재클릭/상단 값 유지/빈 안내 중앙 실측.

## 9. UX-008 — 오늘 작업 추가·제거
1. 목록 마지막에 ‘작업 추가하기’, 각 행 오른쪽 작은 휴지통 제거 버튼. PC/키보드/좁은 화면에서 접근 가능하며 중복 조작을 잠근다.
2. 추가 폼은 이름과 완료 여부/목표 횟수 유형, 횟수일 때 목표만 받는다. 이름 1~80자, 목표 정수 1~1,000,000, 최대 50개. 빈 목록도 허용하며 달성률은 0/0·빈 잔디다.
3. 작업 변경은 서버 기준 오늘부터 적용한다. 같은 날짜의 변경은 그날 최종 목표 집합으로 갱신하고 과거 날짜 집합/체크는 유지한다. 제거는 목표 집합에서 제외하며 체크 레코드를 파괴하지 않는다.
4. goalConfig는 날짜별 revisions/fromDate/goals 및 낙관적 version을 저장한다. 이전 DB/백업은 기본 4개 목표 집합을 사용한다. 백업/복원은 이력과 버전을 포함하며 오래된 변경/제거된 작업 체크를 거부한다.
5. MCP add_goal/remove_goal은 open_dashboard의 goalConfigVersion을 확인해 호출한다. 불확실한 응답은 재조회하고 추가를 맹목 재시도하지 않는다.
6. 코드: TaskEditor.tsx, Checks.tsx, main.tsx, src/contracts/experience.ts, src/application/journal.ts, service.ts, src/domain/goals.ts, src/mcp/main.ts. 수용: 추가/제거/재시작·횟수/과거 분모 보존/충돌/복원/0개.


## 10. UX-009 — 노트북 기본 창에 맞는 밀도
1. 달성/연속 지표 왼쪽, 목록 오른쪽. 동일 좌우 비율 유지하며 목록 스크롤바는 바깥 우측에 위치한다. 기존 왼쪽 목록 요구를 대체한다.
2. 기본 폭 최대 760px, 상단 도구 높이 32px, 작업 행 약 32px, 목록 최대 164px. 목록이 많을 때 목록 내부만 스크롤한다. 상단/하단 간격 12~16px, 잔디 범례는 제거한다.
3. 사진은 비율을 유지하며 낮은 창 높이에 맞춰 축소한다. 사진을 자르거나 페이지 overflow:hidden으로 내용을 숨기지 않는다. 과거 내역 목록은 영역 내 스크롤한다. 좁은 모바일은 단일 열과 세로 스크롤을 허용한다.
4. 수용: 실제 React/합성 SQLite에서 콘텐츠 960×640, 800×600, 720×540, 600×480의 오늘/과거 화면에 가로·세로 페이지 스크롤 없음. 세로 사진·피드백 3개·16개 작업·6주 달력에서도 전체 넘침 없음. 기존 체크/설정/날짜/작업 동작 및 360px dark 회귀.
5. 실제 MacBook 기본 해상도/Codex 기본 창 실측은 이 Windows 환경에서 미검증. 브라우저 콘텐츠 영역 시험과 구분하며 호스트 수용 시 실제 창 크기를 기록한다. 코드: ui/src/compact.tsx, compact.css, scripts/test-journal-ui.mjs.


## 11. UX-010 — 공통 스크롤 공간
1. 페이지 html과 공통 ScrollArea(HAS-A)에서 scrollbar-gutter:stable을 적용한다. 체크리스트, 과거 내역, 알림 목록은 공통 컴포넌트를 사용한다. textarea도 같은 정책이다. 이미지 클리핑처럼 스크롤이 아닌 overflow:hidden 영역에는 적용하지 않는다.
2. 설정을 하단에 펼쳐 세로 스크롤이 생겨도 대시보드의 가로 위치/폭은 유지한다. 내용 숨김으로 페이지 스크롤을 감추지 않는다. 브라우저 overlay scrollbar에서는 실제 공간이 없을 수 있다.
3. 코드: ui/src/ScrollArea.tsx, compact.css, compact.tsx, Imagebook.tsx, ReminderPanel.tsx. 수용: classic scrollbar 폭 15px 강제 후 설정 전후 대시보드 x/width 동일, root computed gutter stable, 기존 낮은 PC/모바일 회귀.

## 12. UX-011 — 개인정보 자동 저장과 계산
1. 저장된 displayName의 프로필 @handle을 읽기 전용 표시한다. 이름/계정/시간대 입력과 프로필·영양 저장 버튼을 제거한다. 실제 dots 계정 연동을 추정하지 않는다.
2. 브라우저 Intl 시간대를 open_dashboard에 전달하고 서버 프로필을 다를 때만 갱신한다. 기존 기록의 절대 날짜는 바꾸지 않는다. 시간대를 보내지 않는 이전 클라이언트는 기존 동작을 유지한다.
3. 한 줄 전체 폭의 나의 목표(300자), 성별·성인 나이·키·체중. 500ms debounce/직렬 낙관적 버전 저장으로 요청 중 후속 입력을 보존한다. 닫을 때 대기 초안을 전송한다. 오류/충돌을 표시하고 덮어쓰지 않으며 충돌 시 다시 열어 최신 값을 확인한다. 오류 시 재시도 버튼만 제공한다. 입력 중 범위 미달 숫자는 로컬 초안으로 허용하고 blur 시 이전 유효값으로 되돌린다.
4. 자동 계산은 유지 열량 추정치다. 자유 목표는 저장해 식단 분석 문맥으로 사용하되 기간/활동 정보 없는 감량·증량 목표에서 열량 부족/초과를 임의 처방하지 않는다. 활동 정보가 없으면 낮은 활동량을 가정한다. 미입력 또는 부적절한 계산 범위에서는 숫자를 만들지 않는다. 기존 수동 목표 API/백업은 호환 유지하며 UI 개인정보를 수정할 때 자동 목표로 전환한다.
5. Mifflin–St Jeor REE = 10×kg + 6.25×cm − 5×나이 + (남성5/여성−161). PAL은 기본1.4, 기존 활동 정보 light1.6/moderate1.8/active2.0은 앱의 근사 매핑. 유지 kcal는 10 단위 반올림, 단백질 참고 최소 성인0.8g/kg(18세0.85), 탄수화물/지방 참고 상한은 kcal의65%÷4,35%÷9. 단백질 올림·상한 내림. 각 최대치는 동시에 먹어야 하는 목표가 아니다. 현재 DB의 calorieMax에는 유지 추정치, calorieMin에는 null을 저장하며 일일 평가는 기존의 추정/불완전 판단 규칙을 유지한다.
6. 운동은 일반 성인 기준 주150–300분 중강도 유산소/근력 주2일 이상. 개인 운동 처방이 아니다. 근거: [Mifflin 원 논문](https://pubmed.ncbi.nlm.nih.gov/2305711/), [NIDDK 활동 수준](https://www.niddk.nih.gov/bwp), [National Academies DRI 요약](https://www.ncbi.nlm.nih.gov/books/NBK208874/), [WHO 운동 권장](https://www.who.int/europe/news-room/fact-sheets/item/physical-activity).
7. 코드: ConfigPanel.tsx, useAutosave.ts, NumberField.tsx, main.tsx, src/domain/nutrition.ts, contracts/experience.ts, journal.ts, mcp/main.ts. 수용: 계산 예시/미입력/범위·버전·백업, 숫자 중간 입력, 느린 첫 저장 중 후속 입력 보존, 재열기/시간대 변경과 과거 날짜 보존. 실제 dots 계정/호스트 시간대 수용은 별도.

## 13. UX-012 — 한 줄 알림 편집
1. 펼친 설정에 라운드 행: 요일 선택/일회성 날짜/간격(분·시간·일) + 시각 + 이름 + 활성/비활성 + 제거. PC 한 줄, 좁은 화면은 줄바꿈. 최대30개, 새 알림은 비활성으로 시작하며 자동 저장한다.
2. 기존 끼니 확인 설정은 요일 알림으로 읽기 호환. 서버 프로필 시간대를 따른다. 간격 기준일은 추가한 날짜, 시각은 설정 시각이다. 일 간격은 현지 달력일, 분·시간은 경과 시간 기준이다. DST에 없는 현지 시각은 건너뛰고 반복되는 현지 시각은 같은 occurrence로 중복 억제한다.
3. 열린 앱에서 15초마다 claim_due_alarms. 요일/일 간격은 해당 날 시각 이후, 일회성은 지난 시각도 한 번 확인, 분·시간 간격은 최신 tick 하나만 확인해 밀린 알림을 쏟지 않는다. claim 로그를 DB/백업에 저장해 다중 화면·재시작의 중복을 억제한다. 제거된 알림의 로그는 정리한다.
4. claim은 at-most-once이며 OS 수신 확인이 아니다. claim 후 UI가 닫히거나 알림 권한이 없으면 실제 수신을 보장하지 않는다. 앱이 닫혔을 때 실행/클라우드/모바일 예약을 만들지 않는다. PC 알림 허용은 사용자 조작 시 요청하고 가능한 환경에서만 표시한다.
5. 코드: ReminderPanel.tsx/useAutosave.ts/ScrollArea.tsx, src/domain/alarms.ts, journal.ts, experience.ts, mcp/main.ts. 수용: 요일·일회성·간격·DST·중복·재시작·백업·구버전 설정, 브라우저 행 추가/수정/활성/제거/재열기.

## 14. UX-013 — 작업 수정과 공통 추가 폼
1. 각 항목 제거 버튼 바로 왼쪽에 연필 수정 버튼. 이름·유형·목표 횟수를 기존 값으로 열고 수정 완료/취소로 닫는다. 유형 문구는 완료 여부/목표 횟수.
2. TaskForm을 추가·수정에서 공유한다. 유형/숫자 높이는 모두34px, 추가(또는 수정 완료)·취소는 별도의 버튼 영역과 경계를 제공한다. 취소는 저장하지 않는다.
3. edit_goal은 goalConfigVersion으로 충돌을 검사하고 오늘부터 목표 이력에 반영한다. 과거 목록/체크 보존. 같은 유형은 오늘 진행량 보존, 횟수 목표 변경 시 달성 재계산. 유형 변경은 의미가 달라 오늘 진행만 초기화한다. 오늘 체크 버전도 올려 오래된 저장이 편집을 덮지 못하게 한다.
4. 코드: TaskForm.tsx, TaskEditor.tsx, Checks.tsx, compact.tsx/compact.css, journal.ts, mcp/main.ts. 수용: 이름/목표 수정·취소·재조회/과거 보존/버전 충돌/백업·유형 전환, 폼 높이 실측과 PC/모바일 회귀.
