# Fitlog 기능별 UX 요구사항

2026-10-11 · 사용자 확정 요청 · [HAN-8](https://linear.app/hanzicho/issue/HAN-8)

## 1. 제품 목적과 범위

원하는 생활관리를 최소한의 노력과 신경 쓰임으로 수행한다. 기본 화면 하나에서 오늘 상태·달성률·연속 기록·날짜별 사진을 확인한다. 체크 또는 짧은 채팅으로 기록하고 불필요한 페이지 전환·설명·입력·재질문을 줄인다. PC 우선이며 모바일은 기본 넘침 방지 후 실제 기기에서 후속 다듬는다.

아래 ID는 이후 수정에도 유지한다. 새로운 요구를 추가할 때 새 ID를 발급하고, 변경 내역은 [CHANGELOG](../../CHANGELOG.md)에 남긴다. 현재 구현/검증 근거와 단계는 [PROJECT](../PROJECT.md), [VALIDATION](../VALIDATION.md)을 참조한다. 과거 DESIGN/설치 문서와 충돌하면 이 최신 사용자 확정 요구를 우선하며 과거 기록은 이력으로 보존한다.

## 2. UX-001 — 필요한 문구와 동작만 제공

- 기본 화면의 “이 호스트는…” 설명, 자동 오버레이 요청과 미지원 안내, 정보 페이지 넘김, 장식용 모듈 칩을 제거한다.
- 오류는 실제 동작이 실패했을 때만 “다시 시도”, “직접 입력”처럼 다음 행동을 짧게 안내한다. 저장 실패·충돌을 감추거나 성공으로 표시하지 않는다.
- 사진/목표의 AI 전송 안내, 분석값이 추정이라는 표시, 삭제 확인은 사용자의 판단에 필요하므로 유지한다. 고급 촬영 폴더 기능은 접힌 설정에 둔다.
- 수용: 최초 로딩 후 미지원 오버레이 안내 없음, 의미 없는 안내를 닫기 위한 추가 동작 없음. 업로드 실패 시 재시도/직접 입력 가능.
- 코드: `ui/src/main.tsx`, `bridge.ts`, `CameraFolder.tsx`, `compact.tsx`.

## 3. UX-002 — 왼쪽 절반에 세로 체크리스트

- PC에서는 오늘 체크리스트가 상단 왼쪽 1/2을 차지한다. 운동·아침·점심·저녁을 한 행에 하나씩 표시한다.
- 목록 높이가 제한을 넘으면 목록 내부만 세로 스크롤한다. 각 행에서 ✓/X/미작성과 실행 상태를 바로 저장한다. 중복 클릭 잠금·버전 충돌 처리·재조회가 적용된다.
- 수용: PC 두 열의 폭이 같고 체크 행이 겹치지 않는다. ✓ 선택, X 선택, 미작성 되돌리기 후 재접속해도 동일 상태이며 채팅을 열지 않는다.
- 코드: `JournalPanel.tsx`의 `Checks`, `compact.tsx`, `compact.css`의 `.daily-overview`, `.checklist-scroll`.

## 4. UX-003 — 오른쪽 지표 동시 표시

- 오른쪽 1/2에 최다 연속 기록·현재 연속 기록·오늘 목표 달성 원형 뷰를 함께 표시한다. 페이지 넘김 없이 확인한다.
- 연속 기록은 활동/사진 또는 실제 확인한 체크가 있는 날을 센다. 예정만 있는 날은 제외한다. 실패 X를 기록한 날도 기록은 남긴 날이다.
- 원형 뷰는 명시적으로 준수한 ✓ 수/N이다. 사진/활동 건수나 연속 기록 수를 달성률로 쓰지 않는다. 전체 해제 시 0/N이다.
- 수용: 체크 저장 후 원형 뷰와 잔디 즉시 갱신, 체크만 기록한 날도 연속 기록에 포함, 활동 건수를 새로 만들어 부풀리지 않음.
- 코드: `DailyMetrics.tsx`, `src/domain/goals.ts`, `progress.ts`, `src/application/service.ts`.

## 5. UX-004 — 아래 날짜별 이미지북

- 상단 아래 여백에 선택 날짜의 이미지북과 월별 잔디를 배치한다. 사진 첨부/카메라 입력은 별도 채팅 없이 가능하다.
- 새 업로드 후 해당 사진을 선택한다. 이전/다음과 현재 장수로 탐색하고, 월별 날짜 선택 시 그날 사진으로 바뀐다. 마지막 사진 삭제 시 간결한 빈 상태로 돌아간다.
- 이미지 주변의 고정 높이·큰 빈 배경·장식 테두리를 없앤다. 이미지 비율을 유지하고 프레임은 렌더된 이미지 크기에 맞춘다. 로딩·빈 상태에는 이미지 크기의 가짜 프레임을 두지 않는다.
- 원본/분석은 로컬 저장한다. 분석 미지원/실패 시 사진을 유지하고 재시도·수정이 가능하다. AI에는 사진과 저장 목표가 전달된다. 직접 입력한 추정값은 명시된 분석 출처로 보관한다.
- 수용: 같은 날 여러 사진 탐색, 날짜 왕복과 새로고침 후 재조회, 신규 사진 선택, 이미지/프레임 폭·높이 일치, 분석 실패 시 사진 유지.
- 코드: `JournalPanel.tsx`, `styles.css`, `compact.css`, `src/application/journal.ts`.

## 6. UX-005 — GitHub 방식의 목표 달성 잔디

- 하루의 목표 집합 크기를 N, 중복 없이 준수 ✓로 저장된 목표 수를 K라 한다. 현재 목표 집합은 운동·아침·점심·저녁으로 N=4이다.
- 0/N은 빈 색, 0<K<N은 비율에 따라 단계적으로 진해지고, N/N만 가장 진한 4단계이다. 현재 0/4, 1/4, 2/4, 3/4, 4/4는 각각 level-0~4이다.
- 일반 N은 중간 농도를 `min(3, ceil(3*K/N))`, 모두 달성은 4로 계산한다. N=0은 0으로 처리한다. 임의 목표 추가/제거 및 날짜별 목표 집합 버전 관리는 이번 범위에 포함하지 않는다.
- X·미작성·예정·활동 존재·사진 첨부·분석 대기는 달성으로 집계하지 않는다. 월/연간과 미니/상세 화면은 같은 서버 계산값을 사용하며 기록 종류 필터로 목표 분모를 바꾸지 않는다.
- 수용: 0~4 색 순서, 중복 체크로 증가하지 않음, 해제/수정 즉시 감소, 미래 날짜 제외, 가변 N/0 처리, 필터 독립성.
- 코드: `src/domain/goals.ts`, `service.ts`의 `snapshot.goals`, `compact.tsx`, `main.tsx`, `styles.css`.

## 7. UX-006 — 체크와 짧은 채팅을 같은 기록으로 취합

- UI 체크는 `set_day_check`로 날짜·목표·준수·실행 상태를 저장한다. 확인만으로 자유 서술 활동 레코드를 만들어내지 않는다.
- 채팅의 명확한 활동 사실은 `get_profile`로 날짜를 해석하고 `create_activity`로 저장한다. 해당 날짜의 체크를 조회해 실행 상태도 반영한다. 같은 요청 재시도에는 같은 idempotencyKey를 사용한다.
- “운동했다/식사했다”는 사실만으로 식단 목표 준수를 단정하지 않는다. 이미 명시된 준수 체크를 보존하고, 새로운 판단은 미작성으로 둔다. 사용자가 준수/미준수를 명시하면 그대로 반영한다. 예정은 실행 완료나 달성으로 저장하지 않는다.
- 날짜·대상·의도가 명확하면 반복 질문 없이 취합한다. 저장 결과가 달라지는 모호함만 질문한다. UI는 저장 revision을 재조회해 같은 상태를 표시한다.
- 수용: 실제 MCP 저장/충돌/재시작 시험과 UI 재조회. 자연어 해석·도구 호출 순서와 실제 호스트 내 자동 갱신은 별도 호스트 수용 대상이다. 독립적인 로컬 자연어 파서는 이번 변경에 추가하지 않는다.
- 코드: `src/mcp/main.ts`의 도구 설명, `src/application/service.ts`, `JournalPanel.tsx`, `main.tsx`.

## 8. DOC-001 / DOC-002 — 변경 기록과 프로젝트 운영

- `CHANGELOG.md`: 날짜별 변경, 요구 ID, 실제 검증/남은 한계. 아직 출시되지 않은 변경은 Unreleased로 둔다.
- `docs/PROJECT.md`: Linear 프로젝트/이슈, 현재 단계, 구현·검증·실제 수용 구분, 단계별 작업/진입 조건/다음 행동.
- README와 AGENTS에서 문서 진입점을 제공한다. Linear와 코드 문서를 함께 갱신하고 전이는 근거·승인 확인 후 수행한다. 문서화나 빌드 통과만으로 다음 단계로 이동하지 않는다.

## 9. 검증 상태

구현 변경 및 자동 검증 결과는 `docs/VALIDATION.md`의 HAN-8 항목에 기록한다. 브라우저는 실제 React와 합성 SQLite를 사용하나 호스트/AI bridge는 모사한다. 실제 Codex 재접속·카메라/폴더·AI·OS 알림·모바일 수용은 해당 근거가 생기기 전까지 미검증이다.
